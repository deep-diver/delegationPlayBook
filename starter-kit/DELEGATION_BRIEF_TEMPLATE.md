# DELEGATION_BRIEF_TEMPLATE.md — 표준 업무 위임 명세서 카드

> 사용법: `PLAYBOOK.md`에 아직 등록되지 않은 신규 업무를 위임할 때 아래 두 양식 중 하나를 복사해 빈칸을 채워 전달한다.

---

## 양식 A. 표준 5요소 업무 위임 브리프 (중요·복합 업무용)

```markdown
## 1. 위임 레벨 선언
- **적용 단계:** [Level 1 (조사 보고) / Level 2 (대안 비교·추천) / Level 3 (초안 완성 후 승인 대기) / Level 4 (격리 폴더 내 선 실행 후 로그 보고)]

## 2. 작업 목표 및 의사결정 맥락
- **최종 목적:** [이 산출물을 보고 내가 내릴 결정 또는 해결하려는 실무 문제 1줄]
- **참조 컨텍스트:** `@USER.md`, `@SOUL.md`, `@PLAYBOOK.md`

## 3. 허용 도구 및 금지 경계 (Scope & Boundaries)
- **읽기 허용 소스:** [`./raw/대상파일.csv` / 지정된 공식 문서 URL 목록] (지정 범위 외 임의 배경지식 혼합 금지)
- **쓰기 허용 위치:** [`./drafts/산출물파일명.md`]
- **절대 금지 행위:** [외부 이메일·메신저 실제 발송 / 원본 파일 수정 / 유료 API 반복 호출]

## 4. 완료 정의(Definition of Done) 및 출력 규격
- **필수 포함 항목:** [비교 표 컬럼명 고정 / 모든 수치 옆 원문 출처 위치 또는 ID 병기]
- **분량 상한:** [핵심 요약 3줄 + 본문 최대 N줄 이내]
- **불확실성 처리:** 근거가 불충분한 항목은 추정하지 말고 `[판단 보류: 사유]`로 별도 분리할 것.

## 5. 인간 승인 게이트 멈춤 지점 (HITL Checkpoint)
- **정지 조건:** [예: 1페이지 논리 개요 작성 직후 / 답장 초안 저장 직후] 즉시 실행을 멈추고 내 검토 승인을 대기할 것.
```

## 양식 B. 5줄 최소 명세 프롬프트 (빠른 일일 위임용 `MINIMAL_SPEC_PROMPT`)

```markdown
[1. 목적]: 이 결과물은 [누가 / 어떤 결정을 내리기 위해] 사용한다.
[2. 입력]: 반드시 [지정 파일 경로 또는 URL] 내부의 사실만 근거로 사용하라.
[3. 경계]: [데이터 추출·초안 작성]만 수행하고, [원본 수정·주관적 추측·외부 전송]은 절대 하지 마라.
[4. 포맷]: [마크다운 5열 표 / 불릿 5개 이내]로 출력하고 모든 수치 옆에 `[원문 출처/ID]`를 적어라.
[5. 예외]: 확인 불가능한 항목은 지어내지 말고 `'확인 불가'`로 표기해 하단에 분리 보고하라.
```
