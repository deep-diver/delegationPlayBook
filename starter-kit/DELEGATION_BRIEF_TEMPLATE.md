# DELEGATION_BRIEF_TEMPLATE.md — 일일 작업 주문서 양식

> 사용법: 아직 `PLAYBOOK.md`에 등록하지 않은 새 일을 시킬 때 아래 두 양식 중 하나를 복사해 빈칸만 채워 던진다.

---

## 양식 A. 꼼꼼한 5칸 작업 주문서 (중요하거나 덩치 큰 업무용)

```markdown
## 1. 어디까지 맡기나 (위임 단계)
- **적용 단계:** [Level 1 (자료만 찾아오기) / Level 2 (비교표와 추천안 가져오기) / Level 3 (초안까지만 짜고 내 결재 기다리기) / Level 4 (초안 폴더에 바로 저장하고 결과 보고하기)]

## 2. 왜 하는 일인가
- **내 목적:** [이 결과물을 보고 내가 내릴 결정 한 줄]
- **함께 읽을 파일:** `@USER.md`, `@SOUL.md`, `@PLAYBOOK.md`

## 3. 봐야 할 곳과 건드리지 말 곳
- **읽을 자료:** [`./raw/대상파일.csv` 또는 공식 문서 주소] (여기에 없는 외부 추측 섞지 말 것)
- **저장할 위치:** [`./drafts/결과물파일명.md`]
- **절대 금지:** [외부 메일·메신저 실제 발송 / 원본 파일 수정 / 유료 API 반복 호출]

## 4. 완성 기준과 결과물 모양
- **꼭 들어갈 내용:** [비교표 열 이름 고정 / 모든 숫자 옆에 원본 위치나 ID 적기]
- **분량 제한:** [맨 위 3줄 요약 + 본문 최대 N줄 이내]
- **애매할 때 처리법:** 자료만으로 판단이 안 서는 항목은 지어내지 말고 `[판단 보류: 이유]` 칸으로 따로 빼둘 것.

## 5. 중간에 멈춰서 물어볼 지점
- **정지 조건:** [예: 1페이지 뼈대 완성 직후 / 답장 초안 저장 직후] 일단 멈추고 내 확인을 기다릴 것.
```

## 양식 B. 바쁠 때 쓰는 5줄 주문서 (`MINIMAL_SPEC_PROMPT`)

```markdown
[1. 목적]: 이 자료는 [누가 / 무슨 결정을 내리려고] 쓴다.
[2. 자료]: 무조건 [지정한 파일 경로 또는 웹 주소] 안에 적힌 사실만 써라.
[3. 경계]: [숫자 뽑기와 초안 작성]만 하고, [원본 수정·내 생각 추측·외부 발송]은 절대 하지 마라.
[4. 모양]: [5열 마크다운 표 / 짧은 목록 5개 이내]로 정리하고 모든 숫자 옆에 `[원본 위치]`를 붙여라.
[5. 보류]: 자료에 안 나오는 내용은 지어내지 말고 `'확인 불가'`라고 적어 맨 아래에 따로 모아라.
```
